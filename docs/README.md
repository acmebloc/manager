# 설계 문서 규칙과 색인

이 폴더의 문서는 "무엇을 왜 그렇게 만들었는가"를 남기는 자리다. 코드가 답해주는
것(무엇을 하는가)은 코드에 맡기고, 코드만 봐서는 알 수 없는 것 — 검토하다 버린
대안, 일부러 하지 않기로 한 것, 그 판단의 근거 — 을 적는다.

## 왜 규칙이 필요했나

한동안 문서마다 상태를 적는 방식이 달랐다. 상단에 굵은 완료 문장을 둔 것, 범위 표에
상태 열을 둔 것, `[x]` 체크리스트를 둔 것, `(확정)` 도장을 문장마다 찍은 것,
취소선으로 지운 것, "본문과 다르면 8장이 맞다"는 우선순위 규칙까지 둔 것. 가장 최근에
쓴 두 문서는 구현 상태 표시가 아예 없어서 배포됐는지조차 문서만 봐서는 알 수 없었다.

결과는 예측 가능했다. 알림·게시판 책장·통합 검색은 **이미 배포됐는데** 다른 문서의
범위 표에는 몇 주 동안 "미룸"으로 남아 있었고, 일감 상태 라벨이
`등록/진행/검수` → `대기/진행중/검수중`으로 바뀌었는데 문서 세 곳이 옛 라벨을 그대로
들고 있었다. 읽는 사람은 어느 쪽이 맞는지 코드를 열어봐야 알 수 있었다.

그래서 **상태를 적는 자리를 한 곳으로 줄인다.**

## 규칙

### 1. 상태 블록 — 문서당 하나, 제목 바로 아래

```markdown
# 일감 관리 설계

> **상태**: 배포완료
> **최종 확인**: 2026-09-18 · `f9e82f5`
> **미진행**: 없음
```

- **상태**는 아래 여섯 중 하나다. 다른 말을 쓰지 않는다.

  | 값 | 뜻 |
  |---|---|
  | `초안` | 아직 합의 전. 내용이 바뀔 수 있다 |
  | `기획확정` | 합의됐고 구현 착수 가능 |
  | `구현중` | 일부만 구현됨 |
  | `구현완료·미배포` | 로컬 검증까지 끝났고 프로덕션에는 안 올라감 |
  | `배포완료` | 프로덕션 반영 및 확인 완료 |
  | `상시유지보수` | 완료/미완료로 나눌 수 없는 운영 문서(런북) |

- **최종 확인**은 `YYYY-MM-DD · \`커밋해시\`` 형식이다. "이 날짜에, 이 커밋의 코드와
  대조해 문서가 맞다는 걸 확인했다"는 뜻이다. 날짜만 적으면 무엇과 대조했는지가
  남지 않아 다음 사람이 다시 전부 대조해야 한다.
- **미진행**은 `없음`이거나 `§7 참고`처럼 목록이 있는 절을 가리킨다.

### 2. 상태는 이 블록에만 쓴다

- 범위 표에 `상태` 열을 두지 않는다. 표는 "무엇을 다루는가"만 적는다.
- `(확정)` 도장, `~~취소선~~`, `⚠` 같은 문장별 표시를 쓰지 않는다.
- **"본문과 다르면 N장이 맞다" 같은 우선순위 규칙을 두지 않는다.** 그 규칙이 필요하다는
  건 본문이 낡았다는 뜻이다. 우선순위를 적는 대신 본문을 고친다.

### 3. 안 하기로 한 것은 `## 하지 않는 것` 절에만

`미룸` · `범위 밖` · `남은 작업` · `미확정` · `나중에 추가` 같은 표현은 이 절 안에서만
쓴다. 본문 곳곳에 흩어지면 "무엇이 아직인지"를 알려면 문서를 통째로 읽어야 한다.

**그 항목을 구현하면 그 줄을 지운다.** 취소선을 긋거나 괄호로 "이건 나중에 했다"고
덧붙이지 않는다. 그리고 상태 블록의 날짜·커밋을 갱신한다.

### 4. 코드와 겹치는 값은 적지 말고 가리킨다

일감 상태 라벨처럼 코드에 단일 출처가 있는 값은 문서에 옮겨 적지 않는다.
`src/lib/taskFields.js`의 `TASK_STATUSES`를 가리키면 된다. 옮겨 적은 순간 그 사본은
언젠가 반드시 낡는다 — 실제로 그렇게 낡았다.

### 5. 표기 통일

- 저장소 파일: 백틱 경로 한 가지로. `` `docs/task-relations-spec.md` ``,
  `` `server/src/routes/tasks.js:120` ``
- 메모리 키: `[[key]]` 한 가지로. 이건 저장소 밖 세션 메모리를 가리키며, 저장소에는
  그런 이름의 파일이 없다
- 날짜: `YYYY-MM-DD`

### 6. 기능을 배포하면 그 커밋에서 문서도 고친다

별도 작업으로 미루면 안 한다. 위의 어긋남은 전부 "다음에 정리하지"에서 나왔다.

### 7. 검사

```bash
npm run docs:check
```

규칙 중 기계로 볼 수 있는 것(상태 블록의 존재·형식·값, 커밋 해시의 실재, 보류 표현의
위치, 낡은 상태 라벨)을 검사한다. 나머지는 사람이 지킨다. 문서를 고쳤으면 커밋 전에
한 번 돌린다.
