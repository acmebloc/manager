# 일감 검수자 / 참조자 / 검수 이력 스펙

작성 2026-09-09. 여러 차례의 검토 라운드를 거쳐 확정된 내용이다. 구현 중에 판단이
필요한 지점은 여기 적힌 근거를 따른다.

## 0. 이 기능이 바꾸지 않는 것

- **상태는 4개 그대로**(`todo`/`doing`/`review`/`done`). 칸반도 4단 그대로다.
  "검수요청/반려/최종완료"는 **동작(action)**이고, 각각 기존 상태 하나에
  대응된다 — 새 상태값을 만들지 않는다.
- **소급 적용 없음**. 기존 일감에 검수자/참조자를 자동으로 채우지 않는다.
  (사용자가 배포 전에 운영의 모든 일감을 완료 처리해두었다 — 2026-09-09 확인.)
- 상위/하위/연결 일감 사이의 **상태 연계성은 이번 범위 밖**이다. 별도 기획으로
  다시 꺼낸다(memory의 `deferred-task-linkage-status-propagation` 참고).

## 1. 상태 라벨

| 값 | 이전 라벨 | 새 라벨 |
| --- | --- | --- |
| `todo` | 등록 | **대기** |
| `doing` | 진행 | **진행중** |
| `review` | 검수 | **검수중** |
| `done` | 완료 | 완료 |

라벨은 다음 **모든** 지점에서 같이 바뀌어야 한다: `src/lib/taskFields.js`,
`server/src/lib/taskFields.js`, `server/src/routes/dashboard.js`(자체
`STATUSES` 배열은 값만 쓰므로 영향 없음), 내보내기(`projectExport.js`는
`taskStatusLabel` 경유), 활동 로그(`taskActivity.js`도 경유), 칸반/목록/워크로드
(모두 `TASK_STATUSES` 경유).

유형(`TASK_TYPES`)의 화면 표시 순서도 **기획 / 디자인 / 개발 / QA**로 맞춘다.

## 2. 새 필드

- `Task.reviewerId` — 검수자 1명, 선택값. 프로젝트 멤버여야 한다.
  **담당자와 같은 사람일 수 없다**(양방향 검증: 담당자를 바꿀 때도, 검수자를
  바꿀 때도 서버가 막는다).
- `TaskFollower` — 참조자 N명. `ScheduleFollower`와 같은 조인 테이블 패턴.
  프로젝트에 참여한 인원만 배정 가능.
- `TaskReview` — 검수 이력(append-only). 아래 3장.

담당자·검수자·참조자 필드는 **일감을 수정할 수 있는 사람 전부**가 바꿀 수 있다
(별도의 좁은 권한을 만들지 않는다).

## 3. 검수 이력(TaskReview)

한 줄이 곧 "누가 언제 무엇을 했는지" 한 건이다. **텍스트는 수정·삭제 불가**.

| 필드 | 내용 |
| --- | --- |
| `kind` | `request`(검수요청) / `reject`(반려) / `approve`(최종완료) |
| `body` | 검수 내용(request) 또는 반려 사유(reject). approve는 없음 |
| `links` | 산출물 링크, 최대 5개. `http`/`https`만 |
| `outputReplaced` | 산출물 파일이 한 번이라도 교체·삭제된 적 있으면 true |
| `createdAt` | 시각 |

- **차수**는 저장하지 않고 이력 순서에서 계산한다 — `request`가 나올 때마다
  1씩 증가하고, 그 뒤의 `reject`/`approve`는 같은 차수에 속한다.
- **산출물 첨부·링크는 `request` 이력에만** 붙는다. `reject`는 사유 텍스트만,
  `approve`는 승인 기록만 남는다.
- 산출물 파일은 기존 `TaskAttachment` 테이블에 `reviewId`를 달아 저장한다 —
  20MB 상한, 확장자 허용목록, 프로젝트 멤버 권한 검사를 그대로 물려받는다.
  일감의 **첨부파일 목록에는 나오지 않는다**(`reviewId: null`로 필터).
- 이력 1건당 산출물 파일은 **1개**. 링크는 최대 5개.

### 산출물 파일 교체·삭제

- **올린 사람만** 지울 수 있다(담당자가 교체되거나 프로젝트에서 빠지면 그
  파일은 아무도 못 지운다 — 확인된 트레이드오프).
- 지운 이력이 있으면 `outputReplaced`가 켜지고, 화면에서 파일명 옆에
  `— 산출물이 변경되었습니다`를 노출한다. **횟수는 세지 않는다.**
- 교체·삭제 사실은 활동 로그에도 남긴다(이력 텍스트는 불변이므로, 파일이
  바뀐 흔적은 로그에만 남는다).
- **완료된 일감의 산출물은 교체·삭제할 수 없다**(8장).

## 4. 상태 전이

`from → to` 조합 중 아래에 없는 것은 전부 거부한다(서버에서 강제 — 드롭다운
옵션을 숨기는 것만으로는 부족하다).

| from | to | 동작 | 할 수 있는 사람 | 필수 입력 |
| --- | --- | --- | --- | --- |
| 대기 | 진행중 | – | 수정 가능한 사람 | – |
| 진행중 | 대기 | – | 수정 가능한 사람 | – |
| 대기 | 검수중 | 검수요청 | 담당자·PM·등록자 | 검수자 + 검수 내용 |
| 진행중 | 검수중 | 검수요청 | 담당자·PM·등록자 | 검수자 + 검수 내용 |
| 검수중 | 진행중 | 반려 | 검수자·PM·등록자 | 반려 사유 |
| 검수중 | 대기 | 반려 | PM·등록자 | 반려 사유 |
| 검수중 | 완료 | 최종완료 | 검수자·PM·등록자 | – |
| 완료 | 진행중 | 재오픈 | PM·등록자 | – |

정리하면 **"검수중에 들어갈 때는 검수요청 팝업, 검수중에서 뒤로 나올 때는
반려사유 팝업"**이다. 앞으로(→완료) 나갈 때는 팝업이 없다.

- 대기·진행중 → 완료 직행은 막는다. 완료 → 검수중 직행도 막는다 — 그래야
  "검수중에 들어간 이력에는 항상 검수 내용이 있다"에 예외가 없다.
- PM·등록자도 **절차는 지킨다**: 검수요청하려면 검수 내용을, 검수중을 되돌리려면
  반려 사유를 반드시 등록해야 한다. 권한이 있을 뿐 예외는 아니다.
- 서버는 일감마다 현재 사용자가 할 수 있는 전이 목록(`allowedTransitions`)을
  계산해 내려준다. 클라이언트는 그것으로 드롭다운/드래그 가능 여부를 만든다.
- 이미 다른 사람이 처리해서 `from`이 어긋나면(칸반을 띄워둔 채 새로고침 안 한
  경우) `이미 다른 사람이 처리했습니다` 메시지로 돌려준다.

### 팝업이 뜨는 지점

칸반 드래그, 목록 뷰의 상태 select, 상세페이지의 상태 select — 세 곳 모두
같은 팝업을 쓴다. 그 외의 확인 팝업(단순 확인 컴펌)은 두지 않는다.

**일감 수정 화면에는 상태 필드를 두지 않는다.** 신규 등록 화면에도 원래 없었고,
상태는 "폼에 담아 저장하는 값"이 아니라 "그 자리에서 바꾸는 값"이기 때문이다 —
수정 폼에 남겨두면 팝업 절차를 우회하는 경로가 된다.

## 5. 담당자 / 검수자 / 참조자 알림

- 검수요청 → **검수자**에게 인앱 + 메일
- 반려 → **담당자**에게 인앱 + 메일
- 최종완료 → **담당자**에게 인앱 + 메일
- 검수중 진입·완료 → **참조자** 전원에게 **인앱만**(메일 없음, 반복 발송 무시)
- 참조자 등록/해제는 **활동 로그에 남기지 않는다.**
- 마감 리마인더는 **공을 들고 있는 쪽**으로 간다 — 검수중이면 검수자,
  그 외에는 담당자.
- `isMine`(내 일감만 보기)은 **담당자 또는 검수자**다. 참조자는 포함하지 않는다.

## 6. 검색

- 산출물 설명(`request.body`)과 반려 사유(`reject.body`)를 검색 대상에 넣는다.
- 결과 뱃지는 `[검수요청]` / `[반려사유]`로 구분해 표시한다.
- 프로젝트 접근 스코프는 일감을 통해 그대로 물려받는다(보관된 프로젝트 제외).

## 7. 엑셀 일괄등록 / 내보내기

- 엑셀 헤더에 **검수자**, **참조자** 열을 추가한다. 참조자는 한 칸에 콤마 구분.
- 참조자 3명 중 1명만 매칭 실패하면 **그 1명만 빼고 경고**한다(행을 버리지
  않는다) — 담당자 매칭 실패 시 "미배정 + 경고"와 같은 정신.
- 담당자와 검수자가 같은 사람인 행은 **검수자만 비우고 경고**한다.
- 내보내기(일감)에 **검수자**, **참조자** 열을 추가한다. 참조자는 한 칸에 콤마.

## 8. 완료된 일감은 잠근다

완료 상태에서는 제목·유형·등급·담당자·검수자·참조자·일자·설명·체크리스트·
첨부파일·산출물 전부 수정할 수 없다. 예외는 두 가지뿐이다.

- **댓글은 계속 쓸 수 있다** — 완료된 일감에 대한 논의를 막을 이유가 없고,
  댓글은 원래 별도 권한 체계다.
- **PM·등록자는 완료 → 진행중으로 재오픈할 수 있다.** 이 예외가 없으면 지금
  전부 완료 처리된 운영 일감이 영구히 동결된다.

구현상으로는 서버가 내려주는 `canModify`가 완료 상태에서 false가 되고
(수정 버튼·체크리스트·첨부 UI가 함께 사라진다), 상태 UI는 `canModify`가 아니라
`allowedTransitions`로 그린다.

## 9. 상세페이지 배치

제목 / 유형·등급·상태 / 설명글 / 담당자·검수자·등록자·일자 / 참조자(전체폭 별도
줄) / 검수·반려 이력 / 체크리스트 / 관계 일감 / 첨부파일 / 댓글 / 활동 로그.

관계 일감의 구성(계층 상자 + 선행·후행·연결 상자)은 `docs/task-relations-spec.md`
참고 — 이 스펙을 쓴 뒤에 선행/후행이 추가됐다.

검수 이력은 **가장 최근 차수만 펼치고** 나머지는 접어둔다. 이력이 길어지면
내부 스크롤을 준다(써보고 불필요하면 뺀다).

## 10. 산출물 링크 입력

`input + [추가] 버튼 → 리스트` 방식. 체크리스트·관계일감·멤버 추가가 모두 이
패턴이라 서비스와 결이 맞고, 링크별 개별 삭제와 즉시 형식 검증이 가능하다
(textarea 여러 줄 입력은 이 앱에 전례가 없다).

- 최대 5개. 프로토콜이 없으면 `https://`를 붙이고, `http`/`https` 외의
  스킴(`javascript:` 등)은 거부한다. 링크는 `rel="noopener noreferrer"`로 연다.
